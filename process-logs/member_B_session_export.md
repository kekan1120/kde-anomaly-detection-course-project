## 一、题目到底要你干什么

### 题目核心
**核密度估计（KDE）** 是最朴素的一种"密度估计"：把每个样本点当成一个小"鼓包"（核函数 K），所有鼓包叠起来，就近似出数据的概率密度曲线

$$\widehat p_h(x)=\frac{1}{nh^d}\sum_{i=1}^{n}K\!\left(\frac{x-x_i}{h}\right)$$

其中带宽 $h$ 决定鼓包有多宽：**$h$ 小 → 曲线崎岖、方差大；$h$ 大 → 曲线平滑、可能把多峰结构抹平**。

**KDE 异常检测**的思路非常直接：密度低的地方就是异常。定义异常分数
$$s_{KDE}(x)=-\log\widehat p_h(x)$$
让"分数越大越异常"。**LOF** 是另一种思路：不看绝对密度，只看"我这点的局部密度比我邻居的局部密度稀多少倍"，因此它是**相对稀疏度**，不是概率密度。

### 作业真正的考点（不是把算法跑通）
任务书要求你从 4 条主线中**选一条深入**，团队规划选的是实验分支，主线是 **"带宽选择准则" + "KDE vs LOF 对照仿真"**，落地为 4 个可证伪假设：

| 假设 | 内容 |
|---|---|
| H1 | 增大带宽 → 更平滑；过小多峰尖锐方差高，过大多峰被抹平 |
| H2 | 正常簇密度不均时，单一全局密度阈值会把**稀疏正常簇的尾部**误报为异常 |
| H3 | 局部密度比较有机会降低异质性带来的误报，但 LOF 对 k 和局部结构敏感，不预设它整体更优 |
| H4 | **正常数据似然最优的 bandwidth ≠ 异常检测指标最优的 bandwidth**（两个目标函数不同） |

最后一个 H4 是整道题最有"思想含量"的点：**老师明确要区分"拟合/重构效果"和"下游检测的泛化性能"**，这是任务书里反复强调的。

### 最容易扣分的地方（任务书第七节列了清单）
1. 把**概率密度值当概率**用（连续分布单点概率为 0，密度可以 > 1）；
2. 写带宽准则时漏掉**样本量 n 和维数 d** 的影响；
3. **异常得分方向前后不一致**，或没说明得分与阈值的关系；
4. 仿真**没固定随机种子、没控制变量**，结果不可复现。

## 四、你的具体工作清单（可直接当 TODO）

### 【阶段 1 —— 主责，最重的一阶段】产出协议四件套

**(1) 数据划分协议**
- `train`：**只含正常样本** → 用于拟合 KDE 和 LOF
- `validation`：**只含正常样本** → 只用于**校准阈值**
- `test`：正常样本 + 预先定义好的异常样本 → **只在参数和流程全部锁定后评估一次**
- ⚠️ 标准化等任何数据变换**只能在 train 上 fit**，再 transform 到 val/test

**(2) 数据生成器规格**
- 二维正常分布 = 双高斯簇，制造**密度异质性**：密集簇中心 $(-2,0)$、协方差 $0.25I$；稀疏簇中心 $(2,0)$、协方差 $I$
- train/val/test 都按固定比例从两簇采样，**必须报告每簇的样本量**
- 另做一个**一维双峰数据**专用于"带宽由小到大"的示意图（这是原理图，**不混进二维性能汇总**）
- 种子：`train=1701`、`val=1702`、`test=1703`（独立种子，写进配置）

**(3) 异常生成器**
- **必做：远端异常** —— 在远离两个正常簇中心的固定区域均匀采样
- **可选：局部/边界异常** —— 在簇边界附近另定义采样分布，保留类型标签
- 异常比例在配置里明示（规划建议 **20%**），真实标签由生成规则**自动产生**，不许手工标

**(4) 参数网格（先定范围，再看结果）**
- KDE 带宽：$h\in\{0.2,\ 0.35,\ 0.5,\ 0.8,\ 1.2\}$（几何网格）
- LOF 邻居数：$k\in\{10,\ 20,\ 35,\ 50\}$，必须小于最小训练样本数
- ⚠️ 如果试跑发现数据尺度不合适，**只能在看测试结果之前**整体平移网格，并**书面记录调整原因**

**(5) 阈值校准规则**
- 每个检测器 × 每个参数配置，**各自**用**正常验证分数的 99% 经验分位数**作报警阈值 → 目标经验误报率约 1%
- 要写清楚：分位数的实现方式（插值方式）、**分数并列（tie）如何处理**
- 声明清楚："1% 只是验证集上的设定目标，不承诺测试集严格达到 1%"

**(6) 指标定义（打分表，也是最容易被 D 追着问的部分）**

| 指标 | 定义要点 |
|---|---|
| ROC-AUC | 衡量排序能力，**不依赖阈值** |
| AP / Average Precision | 必须注明用的是哪个库函数及具体计算定义，并**报告测试集异常比例**（AP 受类别比例影响） |
| 阈值处 P / R / F1 / 混淆矩阵 | 默认操作点必须报 |
| 总体正常样本经验误报率 | — |
| **分簇误报率** | 密集簇、稀疏簇**分别**报，这是 H2 的直接证据，别让总量掩盖问题 |
| 分类型异常结果 | 如果异常有多个类型，分层报告 |

## 六、你开工前必须记住的 6 个坑

1. **LOF 必须用 `novelty=True` 模式**，只在训练正常样本上 fit，否则不能给新样本打分
2. **`KernelDensity.score_samples` 返回的是 log density**，异常分数要取负号；**LOF 的 `score_samples` 在不同库/版本里符号可能相反**，必须实测确认，然后写一个断言（"明显正常点分数 < 明显远端异常点分数"）
3. **测试标签绝对不能参与**带宽、k、阈值或任何选择——你一旦看了测试 AUC 去调网格，整份实验的可信度就没了
4. **总误报率好看不代表没问题**——稀疏正常簇的误报率才是 H2 的证据，必须分簇报
5. **AP 依赖异常比例**，报告时必须同时给出测试集异常比例，否则数字没有可比性
6. **规划里"加大带宽通常更平滑"这类话不能当定理写**，偏差/方差的收敛阶依赖光滑性假设、核函数、n 和 d——这条是 A 的理论区，但你设计网格时会用到，别在协议里写过头的因果承诺

## 空区紧凑簇是什么

字面意思：在**离两个正常簇都很远的空白区域**里，再放一个**小而紧**的高斯簇。

$$N\big((0,5),\ 0.1225\,I\big),\quad\text{sd}=0.35$$

当前核心测试集的异常是「远端环」（绕原点 `r∈[5,7]` 均匀撒的点）；这个是另一种形态——**一团抱团的异常**，不是散点。

## 我当初为什么以为有用（以及错在哪）

我的推理是：它离正常簇很远 → 绝对密度极低 → **KDE 判异常**；它内部点彼此很近 → 局部密度高 → **LOF 判正常**。于是两者拉开差距。

**错在 LOF 的模式上。** 我们协议强制 `novelty=True`：LOF **只在 600 个训练正常样本上拟合**，再给新点打分。这种模式下，新点的局部可达密度是**相对训练集**算的——

> 一个离训练集很远的点，`reach-dist` 由「到训练集的距离」主导 → 局部可达密度必然很低 → **LOF 反而判它异常**。

教材里「LOF 对空区紧凑簇失效」的结论，前提是 LOF 跑在**整个数据集上**（簇内点互为最近邻）。两种语义完全不同，我把它们混淆了。

## 实测结果

写了 `probe_hard_cases.py`，在纯坐标上测（**不使用任何测试标签**，h\*=0.35、k\*=20，阈值按协议校准）：

| 候选构造 | KDE 判异率 | LOF 判异率 | 判定 |
|---|---:|---:|---|
| **空区紧凑簇 sd 0.35** | **100%** | **100%** | 两者都判异常 |
| **空区紧凑簇 sd 0.10** | **100%** | **100%** | 两者都判异常 |
| 远端环 `r∈[5,7]`（现有核心） | 99% | 97% | 两者都判异常 |
| 密集簇尾部 3.5σ | 15% | **59%** | 只有 LOF 判异常 |
| 稀疏簇尾部 3.5σ | 87.5% | 73.5% | 两者都判异常 |
| 两簇之间的谷 | 0% | 0% | 两者都判正常 |
| 密集簇内部 | 0% | 0% | 两者都判正常 |

**空区紧凑簇在 novelty 模式下就是一个远端异常**，加它等于多加一批同类样本，白白扩大实验范围。

唯一真正有区分度的是「密集簇尾部 3.5σ」（KDE 15% vs LOF 59%），但那个区域和稀疏簇的**正常**质量重叠，标成异常会造成我上次修的同一个毛病——标签自相矛盾。所以也不能用。

## 那 AUC 饱和怎么办

**不需要新异常类型**，两件事已经解决了：

1. **等价错排配对数**（已加的指标）：h=0.10 是 256 对、h=1.20 是 34 对，**差 7.5 倍**。AUC 只差 0.0009，看不出来，换成对数就清楚了。
2. **分簇误报率**（协议本来就要求）：**KDE 稀疏簇 11/500、密集簇 0/500；LOF 是 4/500 与 5/500**。

第 2 条才是 H2/H3 的真证据，而且过了 10 个种子重复。**两种方法的差异本来就在「误报怎么分配」上，不在「能不能检出」上**——这个结论反而更干净，因为它正好落在研究问题 3（密度估计质量与检测效果是否一致）上。
