# KDE异常检测课程项目计划

## 1. 项目目标

建议项目题目为《带宽与局部密度结构对异常检测的影响：核密度估计与LOF的对照研究》。项目选择实验分支，主线是分析KDE带宽对密度估计和异常检测的影响，并与LOF在同一数据条件下比较。KDE与LOF的比较是解释带宽实验的对照背景，不扩张成算法综述。

研究问题如下。

1. 在正常数据包含不同密度簇时，KDE带宽如何改变正常区域的密度估计及异常得分排序？
2. 以正常验证集校准相同目标误报率后，KDE与LOF对不同类型测试异常的检测表现有何差异？
3. 密度估计质量和异常检测效果是否一致？哪些参数、数据结构和阈值设定会限制结论？

预先写下可证伪假设，实验后根据实际结果接受、拒绝或修订解释。

- H1：在固定训练样本下，增大KDE带宽会使估计密度更平滑。带宽过小时曲线更局部且方差更高，带宽过大时多峰结构可能被抹平。
- H2：当正常簇密度不同，单一全局密度阈值可能把稀疏正常簇的部分尾部误报为异常。
- H3：局部密度比较有机会降低部分密度异质性带来的误报，但LOF对邻居数和异常的局部结构敏感，不预设它整体优于KDE。
- H4：以正常数据似然选出的带宽与异常检测指标最优带宽可能不同，因为两个目标函数不同。

课程任务书未指定必须验证以上全部假设。团队确认后可以合并H1和H4，以带宽敏感性作为唯一主线。

## 2. 课程要求与边界

课程评分为100分。人机协作流程占55分，其中同一对话内完整交互并提供链接占30分，人工识别、举证和修正模型错误占15分，归纳可复用协作范式占10分。专题论文占45分，其中概念和公式准确占20分，验证设计与结论依据占15分，局限与适用边界占10分。

任务书明确要求区分概率与概率密度，讨论带宽与样本量、维数等因素，定义异常得分和阈值，固定随机种子，并控制变量和人工核验。任务书给出的交付口径是两部分合并为一份文档，课程截图写两份文件。准备阶段分别维护“人机协作流程记录”和“专题探究论文”，另保留合并副本，最终按提交入口当前要求打包。

每位成员用本人账号下的一个连续会话完成自己负责的课程报告工作，并在流程记录中提供该会话完整分享链接。小组不能用组长链接替代其他成员链接。封面记录四名成员、组长、分工和工作量。参考文献由成员查原文并核验，不采用未经核对的模型生成引文。

工时和进度均为规划值。截图未提供可确认的当前截止时间，启动时由组长向课程平台确认后改成实际日期。默认基线约2周，各阶段以交付门为准，不以日历天数代替验收。

## 4. 项目阶段与验收门

### 阶段0：立项和开工约束

3. 建共享目录和任务看板，建立四份个人AI过程记录。
4. 约定代码语言、依赖、数据和图表命名规则。建议把随机种子、参数和路径存入配置文件。

**交付物**：一页项目章程、姓名与责任表、里程碑日期、文件清单。

**验收标准**

- 题目、主问题、主线和分支都已写明，范围没有扩展成多算法综述。
- 四人各有一项明确主责、一项互审责任和个人会话记录位置。
- 截止日期及两文件/合并文件提交格式已从课程入口确认，或在看板注明待确认责任人与日期。
- 每个假设都有能观测的变量和可推翻它的结果描述。

**未通过时**：不进入大规模实验。先补负责人、研究问题或提交信息。

### 阶段1：理论、数据与实验协议

**负责人**：A负责理论，B负责协议，C提供实现可行性审查，D检查读者理解和论文结构。

**A工作流和验收**

1. 写KDE密度估计定义，解释n、维数d、核函数K和带宽h。
2. 给出高斯核和均匀核的定义及使用说明，注明核函数归一化约定。
3. 解释小带宽和大带宽各自的现象，避免将概率密度叫作概率。
4. 定义异常分数，建议$s_{KDE}(x)=-\log\widehat p_h(x)$，确认分数越大越异常。
5. 解释LOF按局部可达密度比较样本与邻域，和KDE全局密度估计的差别及失效场景。
6. 每个关键事实至少有可追溯的教材、原论文、官方文档或权威文献来源，记录页码/章节/URL/DOI和访问日期。

**A验收标准**

- 公式中每个符号在首次出现处定义，概率和概率密度区别准确。
- KDE得分方向、阈值判定方向在全文一致。
- LOF不是概率密度估计，比较维度描述准确。
- 文献条目可定位到真实来源，引用所支持的具体论断明确。
- B或D能不看模型原答复，复述公式与分数方向并通过一个手算特例。

**B工作流和验收**

1. 先定正常数据训练、正常验证、混合测试的划分协议。
2. 设计密度不同的两个正常二维簇，并定义训练集、正常验证集及测试集的采样方式。
3. 定义测试异常生成器，至少包含远端异常。局部或边界异常作为核心情形或扩展情形之一，需写明真实标签规则。
4. 定义固定的KDE带宽网格与LOF邻居数网格。先确定范围，再看结果，不能按测试表现改网格。
5. 规定两个检测器的阈值分别由正常验证集分数的99%分位数确定，作为目标经验误报率约1%的操作点。另报告不依赖单一阈值的排序指标。
6. 写清主比较和参数敏感性实验各自一次只改变什么。

**B验收标准**

- 数据生成器能给定种子复现相同数据，正常标签与异常标签由生成规则自动产生。
- train、validation、test用途分离，标准化等数据变换只在训练数据拟合。
- 测试标签不参与带宽、邻居数、阈值或其他选择。
- KDE与LOF阈值都按各自正常验证分数校准，异常得分方向统一。
- 对随机种子、样本量、簇尺度、异常位置、参数网格和指标均有书面记录。
- B和C交叉走查协议后，对每个异常类型的构造和评价方式达成一致。

**阶段1共同门**：A的理论表、B的协议和C的可行性检查一致。任何打分定义冲突或数据泄漏未解决时不得开始结果解释。

### 阶段2：实现与小规模验证

**负责人**：C主责，B提供协议，A核验公式，D核验输出可读性。

**实现工作流**

1. 将生成数据、拟合检测器、计算分数、阈值校准、计算指标和绘图拆成可复用模块或明确步骤。
2. 使用固定且单独记录的随机种子生成训练、验证和测试集。
3. KDE用训练正常数据拟合。LOF使用支持新样本评分的novelty模式，只在训练正常样本上拟合。
4. 对KDE从score_samples取得log density，再取负数定义异常分数。对LOF核对score_samples的符号，必要时取负号。写一个单元级检查确保两个模型都是分数越大越异常。
5. 在正常验证数据上单独为每个模型和参数配置校准阈值。记录分位数实现方法和并列分数处理方式。
6. 先运行少量样本冒烟测试，再运行全量预注册网格。保存参数、版本、种子、阈值、结果和运行时间。

**C交付物**：源码、依赖版本或环境文件、实验配置、运行说明、汇总CSV/JSON、执行日志。

**C验收标准**

- 新环境按说明可从原始种子重建数据并运行主实验。
- 两模型都只用训练正常样本拟合。训练、验证、测试之间无样本重用或标签泄漏。
- KDE和LOF异常分数方向经人工构造的“明显正常点/明显远端异常点”检查通过。
- 阈值仅用正常验证分数计算，测试集只在参数和流程锁定后评估。
- 至少一次由C以外成员在干净运行中复现核心结果，核心数值在预先约定的容差内一致。
- 代码输出包含参数、种子、分割标识、阈值及全部约定指标，不能只保存截图。
- 全量试验前的小规模结果已由A或B人工核对至少一组密度分数和异常阈值。

### 阶段3：正式实验与结果冻结

**负责人**：C执行，B监督协议，D接收结果，A参与解释。

**核心实验矩阵**

| 实验 | 固定项 | 改变项 | 主要输出 |
|---|---|---|---|
| 1D带宽示意 | 同一组样本、核函数、绘图区间 | 小/中/大三个带宽 | 密度曲线、峰结构和平滑程度 |
| KDE敏感性 | 数据划分、异常比例、核函数、阈值规则 | 预先确定的带宽网格 | 测试指标、误报率、密度/得分图 |
| LOF敏感性 | 数据划分、距离度量、阈值规则 | 预先确定的邻居数网格 | 测试指标、误报率、得分图 |
| 方法对照 | 相同train/validation/test和异常标签 | KDE与LOF，参数选择规程固定 | ROC-AUC、AP、校准阈值下混淆矩阵 |

用于主结论的比较可以报告全部参数曲线，并指定不看测试结果的默认参数或只根据验证目标选择的参数。带宽也可以用正常验证对数似然选择，但该选择衡量密度估计目标，必须与异常检测表现并列说明，不能将测试指标最优带宽冒充无偏比较。

**固定指标定义**

- ROC-AUC衡量异常分数排序能力，不依赖某一阈值。
- Average Precision/AP须注明库函数或计算定义，并记录测试集中异常比例，因为AP受类别比例影响。
- 阈值处报告precision、recall、F1、混淆矩阵和正常样本经验误报率。
- 对密度异质性报告稀疏正常簇的独立误报率，避免总指标掩盖问题。
- 若异常样本组成多个类型，分类型报告结果，并报告整体测试异常比例。

**B工作流和验收**

1. 用配置清单逐项核对运行结果与预注册参数网格。
2. 核对数据规模、标签数、缺失值、阈值计算、分数方向、指标和运行日志。
3. 选择每个主图的底层CSV/结果记录并追溯到运行参数。

**D工作流和验收**

1. 从机器可读结果生成图表，避免手工抄数。
2. 每张图标注数据设定、横纵轴、参数、分数方向、阈值或重复次数。
3. 选择主结论所需的最少图表，至少包括1D带宽曲线、参数敏感性结果和方法对照结果。

**阶段3验收标准**

- 所有测试结果来自冻结的参数和流程。
- 图表能从结果文件重建，图中数值可追溯到机器可读输出。
- 每项结论都有对应指标或图表，不用训练拟合效果代替测试泛化表现。
- 测试表现与假设不一致时，保留原结果并讨论，不因结论不理想而回调参数。
- 不存在未解释的种子、样本或运行配置差异。

### 阶段4：可选拓展与边界分析

**原则**：课程评分表没有单独列明“加分题”或额外奖励分。下面项目是提升分析可信度和论文完整度的拓展，只有核心实验、复现和记录全通过后再做。每次最多选一到两项。

| 优先级 | 拓展内容 | 增加价值 | 验收条件 |
|---|---|---|---|
| P1 | 多个预先公布的随机种子重复运行 | 显示结果稳定性和随机波动 | 报告每个种子的结果、均值及标准差或区间，种子列表在看测试结果前确定 |
| P1 | 增加局部/边界异常类型 | 检查局部方法与全局方法的不同优势 | 生成规则、真实标签、异常比例预先记录，主结果按异常类型分层报告 |
| P1 | KDE正常验证对数似然带宽与异常验证指标带宽对比 | 显示拟合目标与下游检测目标的区别 | 任何参数选择只用训练/验证信息，测试仅用于一次最终报告 |
| P2 | 污染训练集敏感性 | 讨论现实中训练数据不纯的情况 | 将污染率作为唯一改变变量，与纯净训练基线独立报告 |
| P2 | 改变特征维数或簇密度比 | 分析高维和密度差异的边界 | 每次只改变一种数据因素，保持其他生成参数固定 |
| P2 | 公开基准数据集复核 | 检查合成数据结论的外部适用性 | 数据来源、标签定义、预处理和划分可追溯，不能替代主实验控制变量分析 |

加分拓展共同验收要求：明确写成扩展实验，记录目的和唯一改变变量，新增复杂度不破坏核心截止时间。若工作量不足，优先完成P1第一或第二项，不同时引入新数据集、多个维度和污染设置。

### 阶段5：论文撰写与人工审计

**负责人**：D整合，A审理论和引用，B审实验协议与指标，C审代码、参数和复现说明。每个人同步维护自己的过程记录。

**论文结构**

1. 摘要，150—250字，含目标、方法、验证方式、主要结果和局限。
2. 引言，背景、问题、研究问题与假设。
3. 原理与定义，KDE、核函数、带宽、异常分数、阈值、LOF对照。
4. 验证方案，数据生成与划分、指标、控制变量、实现、随机种子。
5. 结果与分析，密度拟合图、参数曲线、方法比较、假设检验。
6. 讨论，带宽和邻居数敏感性、密度异质性、阈值、维数、合成数据局限。
7. 小结与参考文献。

**D整合验收**

- 摘要符合字数范围，关键词3—5个。
- 各图表在正文有引用、有解释，轴名、图例、样本数和参数齐全。
- 论文中的数字与冻结结果文件逐项一致，四舍五入规则一致。
- 结论只覆盖实验支持的情形，局限至少分别讨论方法、实验设计和合成数据假设。
- 公式、符号、单位和分数方向全文一致。

**A引用验收**

- 参考文献来源真实可查，作者、标题、出版信息和链接/DOI匹配原文。
- 文中引用确实支持所对应的具体陈述。
- 不存在只由模型提供而未找到原文的引用。

**阶段5共同验收**

- 另一位未主笔者从头到尾通读，列出并关闭概念、数值、图表和引用问题。
- 按任务书的20/15/10三项报告评分标准逐项打勾。
- 如果正文陈述与数据不一致，以冻结结果为准并修正文稿。

**最终验收标准**

- 四份个人记录均有本人账号下的完整会话分享链接，链接可访问并对应实际负责内容。
- 每份记录包含真实提示、关键模型输出、人工核验动作及结果。
- 每人至少总结自己稳定使用的协作做法。小组另有一节归纳共同范式。
- 小组范式包括先限定问题和符号、再逐步推导、用小例子验证、产生代码后检查数据泄漏与分数约定、最后独立审查结论。
- 两份独立内容齐备，合并版也可生成，最终按课程入口要求提交。
- 封面有组员、组长、分工、工作量。提交前由A和D双人核对文件可打开、链接有效、命名清楚。

## 5. 实验协议建议

以下是一种可执行的默认合成数据协议，阶段1可以根据团队试跑调整尺度，但调整应发生在锁定正式实验之前。

### 数据生成

- 二维正常分布采用两个高斯簇形成密度异质性。例如密集簇中心$(-2,0)$、协方差$0.25I$，稀疏簇中心$(2,0)$、协方差$I$。建议正常训练、验证、测试均按固定比例从两簇生成，并报告每簇样本量。
- 训练集只包含正常样本。验证集用正常样本校准阈值。测试集包含新的正常样本和预先定义的异常样本。
- 远端异常可由远离两正常簇中心的固定区域均匀采样。异常比例在配置中明示，例如20%。若增加局部异常，应另外定义边界附近的采样分布并保持类型标签。
- 至少设置一个一维双峰数据用于展示带宽变化。它是原理图示，不混入二维检测性能汇总。
- 随机性建议登记为独立种子，例如train=1701、validation=1702、test=1703。拓展的重复实验另用预先公布的种子列表。

建议用一份主配置文件保存每个簇的样本数、均值、协方差、异常范围、测试异常比例、随机种子、参数网格和阈值分位数。数据字典说明各数组的样本数、维数、标签编码和用途。

### 参数和阈值

- KDE主参数为Gaussian kernel带宽。可在初步尺度检查后预先设定对数或几何网格，例如$h\in\{0.2,0.35,0.5,0.8,1.2\}$。若数据尺度明显不同，可在看测试结果前整体调整范围并记录原因。
- 一维图可用3个代表带宽。二维正式敏感性至少覆盖偏小、中间和偏大的设定。
- LOF使用相同训练样本与欧氏距离，邻居数可设为预先固定的列表，例如$k\in\{10,20,35,50\}$，并确保小于最小训练样本数。
- 对每个检测器和参数，仅以正常验证分数的99%经验分位数设报警阈值。此目标只表示验证集经验误报率的设定，不承诺测试分布严格达到1%。阈值并列时按预先声明的量化方法处理。
- 对每个参数报告ROC-AUC、AP、正常测试误报率、异常召回率。报告默认操作点的precision、recall、F1及混淆矩阵。
- 不同密度簇分别统计正常误报率，避免只报总体误报率。

## 6. 公式和概念核对表

KDE估计式可写为

$$
\widehat p_h(x)=\frac{1}{nh^d}\sum_{i=1}^{n}K\!\left(\frac{x-x_i}{h}\right),
$$

前提是采用此处相应的核函数缩放和带宽约定。不同教材也可将$h^{-d}$并入核函数定义，全文保持一致。

异常分数统一约定越大越异常。

$$
s_{KDE}(x)=-\log\widehat p_h(x).
$$

KDE估计的是密度。连续分布中单点概率为0，区间或区域概率通过对密度积分得到。密度数值不要求落在$[0,1]$。

LOF比较样本局部可达密度与邻域样本局部可达密度。它反映局部相对稀疏程度，不输出KDE意义下的概率密度。不同库的LOF函数可能以负分数编码异常程度，正式代码应依赖实测与文档确认符号，而不能只按名称推断。

带宽增大通常增加平滑程度。偏差、方差如何变化及最优带宽阶依赖光滑性、核函数、样本量和维数等假设。不要将单次二维仿真的图形当作普适收敛证明。

## 7. 关键风险与处置

| 风险 | 早期信号 | 处置方法 |
|---|---|---|
| 测试集泄漏 | 反复根据测试AUC改带宽或阈值 | 锁定协议，重新从验证流程选择参数，测试仅保留最终评估 |
| 得分方向错误 | 明显远端异常分数反而更低 | 用人工样例断言，依据文档检查API返回方向 |
| KDE似然与检测目标混淆 | 只报告正常验证似然并称检测效果最佳 | 同列密度拟合目标与测试检测指标 |
| LOF模式不适合新样本 | 训练得分和测试得分API语义不同 | 使用novelty模式，只在训练正常数据拟合，明确函数及符号 |
| 稀疏正常簇被总指标掩盖 | 总体FPR小但某正常簇误报明显 | 分簇报告正常误报率与得分分布 |
| 单次随机结果不稳定 | 结论对某个种子敏感 | 核心完成后增加固定多种子拓展，报告离散程度 |
| 工时被扩展实验耗尽 | 同时加入真实数据、污染、维数和多种异常 | 冻结核心范围，先完成核心验收再选一项P1 |
| 过程分数最后补写 | 缺提示原文或个人链接 | 每阶段由个人同步记录，提交门前逐项查链接 |
